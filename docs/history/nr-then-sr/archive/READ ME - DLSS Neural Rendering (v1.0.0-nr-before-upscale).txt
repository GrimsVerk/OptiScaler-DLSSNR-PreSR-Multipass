DLSS 5 Neural Rendering for OptiScaler
======================================
an attempt at DLSS Neural Rendering, by dag
with the before-the-upscaler mode by GrimsVerk

This is OptiScaler with an extra pass: NVIDIA's Neural Rendering model, run over your frame to
synthesise detail. NVIDIA ships no public integration for it, so it is driven directly. Nothing here
is officially supported and none of it is documented by NVIDIA.

The colour composition -- how the model's answer is brought back into your frame -- is taken from
RenoDX's DLSS 5 addon by clshortfuse (github.com/clshortfuse/renodx), used under its MIT licence. See
Licenses/RenoDX_ATTRIBUTION.txt. It is their design and it is the reason the colour holds together.


Installing
----------

1. Extract every file in this archive into the game folder -- the one holding the game's .exe. For most
   games that is where the executable sits; for Cyberpunk 2077 it is bin\x64, for Unreal games it is
   <Game>\Binaries\Win64 (Jedi Survivor: SwGame\Binaries\Win64).

2. Run setup_windows.bat and answer its questions. It renames OptiScaler.dll to whatever the game will
   load (dxgi.dll suits most DirectX 12 games) and writes an uninstaller next to it.

3. Put nvngx_dlssnr.dll in that same folder.

   This is the model itself. It comes from an NVIDIA driver package and cannot be shipped here, so you
   have to supply it. One copy per game -- there is no shared or system-wide location, and no way to
   install it once for everything.

   The installer looks for it and tells you whether it is there.

4. Launch the game, open the OptiScaler overlay (Insert), and turn on "Enable Neural Rendering" under
   DLSS Neural Rendering. It is off by default.


What it needs
-------------

- An RTX 50 series card. The model does not run on anything older.
- A driver new enough to ship nvngx_dlssnr.dll.
- A game that already uses DLSS, on DirectX 12.

That last one is not a limitation of the model so much as of how it gets its inputs. Neural Rendering
needs depth and motion vectors, and rather than hunting for them in the game's own frame graph, this
reads the ones the game already hands to DLSS every frame. That is what makes it work in any DLSS title
without per-game work -- and why it does nothing in a game that has no DLSS to intercept.

DirectX 11 games work through the same interception -- the pass rides the D3D11-on-D3D12 bridge that
already carries their upscaler, so nothing extra is needed. Native Vulkan runs the model after the
upscaler only.


If it does not run
------------------

The overlay says why, under the enable checkbox, rather than failing quietly. The usual answers:

  "nvngx.dll_dlssnr.dll is missing"   That file is part of this archive. Extract all of it.
  "nvngx_dlssnr.dll was not found"    Step 3 above.
  "the model would not initialise"    Usually an older card or a driver without the model.

OptiScaler.log in the same folder has more, if logging is on.


Where it runs: the Stage control
--------------------------------

The model can run on either side of your upscaler. The "Stage" dropdown in the overlay picks, live,
with no restart.

  After the upscaler    The original design. The model is shown the finished, display-size frame
                        immediately after DLSS has written it, on the same command list, before the
                        interface is drawn. The model never sees your HUD, so it cannot synthesise
                        detail into text and icons. Its cost scales with your display resolution: at
                        4K it works on four times the pixels the game rendered.

  Before the upscaler   New in this fork. The model is shown the game's render-resolution frame -- the
                        picture DLSS is about to enlarge -- and DLSS is handed the edited copy. The
                        model works on the smaller picture, so its time and its memory fall with the
                        upscaling ratio squared: at 4K DLSS Performance, measured in Jedi Survivor on
                        an RTX 5080, the model went from 11.7 ms per frame to 3.6 ms, and its VRAM
                        working set shrank in the same proportion. Everything after the upscaler --
                        frame generation, the interface -- is untouched, and the game's own frame is
                        never written.

                        The trade: the model was trained on finished frames and here it sees a
                        jittered, aliased one. It re-decides edges every frame, and DLSS then enlarges
                        that. It shows as a slightly fuzzy, unstable silhouette on moving characters,
                        most visible at Detail strength 1. Lowering Detail strength scales it down in
                        proportion; there is no other fix that survived testing.

Stack the two savings if you need to: "Before the upscaler" plus a lower "Model resolution" runs the
model on a fraction of an already-smaller picture. That is the combination to try on a card that is
short of memory or time.

With frame generation, the pass runs once per rendered frame and generated frames inherit the result.
It costs one run per rendered frame, not per presented frame.

Reports wanted: whether "Before the upscaler" makes this usable on a 12 GB card at 1440p, and at what
settings. The overlay shows the pass's cost per frame under the enable checkbox.


How your frame is put back together
-----------------------------------

The model is shown a display-referred version of the frame, because that is the kind of picture it was
trained on. What it hands back is not treated as a difference to add onto your frame -- it is a
complete picture in its own right, rescaled so its brightness sits where your original says it should,
with its hue held in place.

That matters because the two controls below then blend between finished pictures rather than adding
anything, so neither can push a colour somewhere the model never asked for. It also means the frame
DLSS receives on "Before the upscaler" is still the game's own jittered render: the model's verdict is
a bounded per-pixel brightness ratio laid over the game's pixels, never a replacement for them.


The controls
------------

Most of them are the model's own and are undocumented; the tooltips say which ones are guesses.

The two that matter most:

  Detail strength    How far the frame moves toward the model's picture. 0 gives back exactly what the
                     upscaler produced -- a true bypass, bit-identical. 1 is the model's picture. Above
                     1 carries on past it, which the model never asked for, but it is the quickest way
                     to see what it is contributing. This is the control to push if you want more
                     effect, and the one to pull back if "Before the upscaler" makes edges restless.

  Colour strength    Whether the model's colour arrives with its light. At 0 you keep the game's own
                     colour exactly and only the brightness carries the model's verdict -- game-accurate
                     colour with the detail. At 1 the model's colour comes too. Both ends are valid
                     pictures, so anywhere between them is one as well.

And two worth knowing:

  Model resolution   Runs the model at a fraction of the frame to save time. Your frame is never
                     reduced; only the model's own work is done small and enlarged, so the picture
                     underneath keeps its detail. Broad shading survives this; fine synthesised
                     structure softens.

  Highlight guard    Caps how much brighter the pass may make any pixel. Lights are where the model has
                     least to say and where rescaling does the most damage; 2x leaves detail intact
                     while making the ugly failures impossible.

Intensity, Style, Preset and the local strengths are NVIDIA's own parameters. They are read when the
model is built, so changing one rebuilds it after a moment's pause.

There is also a debug view. "Difference" shows what the model changed, amplified: a flat grey frame there
means it is doing nothing. And the pass can write a set of matched before/after frames to a
dlssnr-capture folder beside OptiScaler -- drop an empty file named dlssnr-capture.trigger there while
the game runs -- so claims about what it does can be measured rather than argued.


A caution
---------

nvngx_dlssnr.dll is about 165 MB and identifies itself as "NVIDIA DLSSNR" in its file properties. A file
of that size named nvngx_dlssd.dll is the Neural Rendering model misnamed, not Ray Reconstruction, and
installing it as Ray Reconstruction will break that instead. Check the version details if you are unsure.
